# 배포 전 점검표와 배포 방법

> GitHub 저장소의 `main` 브랜치에 올리면 GitHub Actions 가 자동으로 빌드해서 GitHub Pages 에 배포합니다.

## 1. 배포 전 점검표

### 내용
- [ ] `docs/CONTENT_TODO.md` 의 임시 문구/사진을 실제 내용으로 교체했다
- [ ] 화면에 "(임시)", "임시 문구"라는 글자가 남아 있지 않다 (`Cmd+Shift+F` 로 "임시" 검색)
- [ ] 현수막, 크레딧의 이름과 문구에 오타가 없다
- [ ] 결혼식 사진·교수님 책·선물 사진을 `public/images/` 에 넣었다

### 개인정보 (링크 공개)
- [ ] **링크를 아는 사람은 누구나 볼 수 있습니다.** 사진에 다른 사람의 얼굴이 있다면 동의를 받았는지 확인하세요.
- [ ] 사진 파일에 위치 정보(EXIF)가 남지 않게 한 번 저장하거나 내보내기를 한 파일을 쓰세요.
- [ ] 행사가 끝나면 사이트를 내리거나 비공개로 바꿀 계획이 있다

### 기술
- [ ] `npm run typecheck` 에 오류가 없다
- [ ] `npm run build` 가 성공한다
- [ ] 처음부터 끝까지 한 번 플레이했다 (신입생·강아지 → 비탈길 → 피자 → 복도 → 702호 → 과제 → 정원 대문 → 보물상자 → 크레딧 → 쿠키 영상)
- [ ] 아이패드 Safari 에서 가로 화면으로 한 번 플레이했다 (탭 조작, 글자 크기, 소리)

## 2. 배포 방법

### 기본: GitHub Pages (자동 배포)
- 코드를 고친 뒤 `main` 브랜치에 커밋·푸시하면 `.github/workflows/deploy.yml` 이 `npm ci` → `npm run build` → Pages 배포를 합니다. 저장소의 **Actions** 탭에서 진행 상황을 볼 수 있어요 (1~2분).
- 처음 한 번: 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 둡니다.
- 주소: `https://<깃허브 아이디>.github.io/<저장소 이름>/`
- 새 버전이 아이패드에서 예전 화면으로 보이면 `public/sw.js` 의 `VERSION` 숫자를 올려서 다시 배포하세요.

```bash
git add -A
git commit -m "문구 수정"
git push
```

### 그 밖의 방법
빌드하면 `dist/` 폴더가 만들어집니다. 이 폴더 전체가 웹사이트입니다.

```bash
npm run build
```

### A. Netlify Drop (가장 쉬움, 계정 필요)
1. https://app.netlify.com/drop 에 접속해 로그인합니다.
2. `dist` 폴더를 화면에 끌어다 놓으면 바로 주소가 생깁니다.
3. 사진을 바꾼 뒤에는 다시 `npm run build` 하고 같은 방법으로 다시 올립니다.

### B. GitHub Pages / Vercel
- 저장소에 올린 뒤 각 서비스의 안내에 따라 `npm run build` 와 출력 폴더 `dist` 로 설정합니다.
- 이 프로젝트는 상대 경로(`base: './'`)로 빌드되므로 주소 뒤에 하위 경로가 붙어도 동작합니다.

## 3. 오프라인 대비 (행사장 와이파이가 불안할 때)

세 가지 방법을 함께 준비해 두면 가장 안전합니다.

1. **홈 화면에 추가 (권장)**: 인터넷이 되는 곳에서 아이패드 Safari 로 배포 주소를 한 번 열고 처음 화면(타이틀)이 뜰 때까지 기다립니다. 공유 버튼 → "홈 화면에 추가". 이후에는 와이파이가 없어도 앱처럼 전체 화면으로 열립니다. (한 번 열어 둔 파일이 아이패드에 저장되어서 가능합니다)
2. **백업 파일 1개**: `npm run build:single` 을 실행하면 `dist-single/ddokddok.html` 이 만들어집니다. 노트북에서 더블클릭하면 인터넷 없이 실행됩니다. (사진을 쓴다면 같은 폴더의 `images` 폴더와 함께 보관하세요.)
3. **노트북을 서버로**: 같은 와이파이(또는 휴대폰 핫스팟)에 노트북과 아이패드를 연결하고 노트북에서 `npm run preview` 를 실행한 뒤, 터미널에 나오는 `Network:` 주소를 아이패드에서 엽니다.

## 5. 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| 예전 화면이 계속 보임 | 서비스 워커가 저장해 둔 예전 파일입니다. `public/sw.js` 맨 위 `VERSION` 숫자를 올리고 다시 배포하세요. 아이패드에서는 Safari 설정 → 방문 기록 및 웹사이트 데이터 지우기 |
| 소리가 안 남 | 무음 스위치, 음량, 🔇 버튼 확인. 타이틀의 "시작하기"를 눌렀는지 확인 |
| 사진 대신 그림이 보임 | `public/images/` 의 파일 이름(`book.jpg` 등)과 확장자가 정확한지 확인 후 다시 빌드 |
| 진행이 꼬였음 | 타이틀에서 "시작하기"를 누르면 새로 시작합니다 (저장이 지워집니다) |
